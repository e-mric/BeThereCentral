# Original community props

The trusted `catalog-v2.json` owns prop IDs, relative local image paths, source crops, intended sizes, paint order, collision footprints and built-in interactions. An imported package names the catalog revision; it cannot supply resource paths. Crops are `[x,y,width,height]`. Images retain their original RGBA bytes. Both consumers aspect-fit and centre a crop inside the authored placement rectangle. Collision is `[x,y,width,height]` in normalized placement-box fractions, or `null` for a nonblocking floor decoration; it represents fictional furniture feet, never real-building geometry.

The original sixteen props are an unchanged copy of the project's generated campus atlas, with its existing source crops. See [pixel art provenance](../../../docs/assets/PIXEL_ART.md). Eight additional sprites were generated with Codex's built-in image generator on 12 October 2026, from original descriptive prompts, without reference screenshots or third-party sprites. Their prompts are in [community-asset-prompts.json](../../../docs/design/community-asset-prompts.json). No paid AI service is needed to use the bundled images. Generated originals are preserved; runtime crops omit transparent padding and stray faint pixels. Asset hashes are recorded in the catalog. The project distributes this original art under its MIT License, separately from any third-party reference artwork.

The hacker workstation is fictional coding-school decoration, not a record of 42 Belgium's equipment. Arcade, wellness and meeting props are imagined. The secret bookshelf opens one trusted white Construct room, with two burgundy chairs and a CRT: a fictional Easter egg inspired by the user's reference, without film screenshots, actors, dialogue or branded assets. The debugging duck offers a small built-in interaction. Secrets never represent real doors or routes.

Character options are trusted enum values in the catalog. Procedural 32×48 pixel parts use a `[16,44]` foot pivot and four facing directions; imported content selects options, never drawing commands. Real-person portrayals and introductions still need that person's approval before distribution.

Do not imply that preset clothing can currently be edited or that a stock fictional sprite represents an approved real resident.

## Architect walking refinement

The current `v1/architect-directions-v1.png` is a **derived runtime atlas**, not an unchanged native generation. It contains front/left/right idle plus eight walking frames and back idle plus the preserved four walking frames (32 cells total). RetroDiffusion MCP generated the accepted front and left sheets from neutral sprites rendered from the already-approved art. Original photographs were not uploaded. Right walking is a deterministic mirror of the accepted left sequence. The native source PNGs and original legacy atlas are archived unchanged in `v1/architect-walk-sources-v1/`; their hashes and the packing recipe are in `architect-walk-recipe-v1.json`. Prompts/settings are in the character prompt record. The provider's right outputs had corrupt colour or planted feet, and both new back cycles had corrupt colour; these failed candidates are not bundled. A provider-side failed inference was refunded before budget accounting.

`python3 content/community/assets/tools/pack_architect_walk.py` (Pillow required) mechanically samples/packs exact RGBA pixels into 64×96 cells. Walking uses a fixed source root per sequence (`[64,107]` for front, `[64,108]` for sides) on each 128×128 cell, then the shared output root `[32,88]`; it never recentres individual feet, recolours, removes backgrounds, fits separate poses or synthesizes intermediate frames. The normalized atlas uses sourceScale1. Existing idle and back-walk hashes remain identical. The build was repeated and matched the atlas, catalog and conformance file byte-for-byte.

Studio preserves a640ms cycle: eight-frame views use80ms, the four-frame back uses160ms. Godot preserves32 world pixels per full cycle with a direction-specific frame count. Manual art and other presets retain their four-frame contract. Sparse green edge pixels from the accepted provider sources remain visible in magnified dark-background inspection; front walking is a restrained shuffle and the eight-frame back upgrade remains unfinished. No production-quality or mobile-animation claim follows from the asset checks.
