# Task plan template

For complex or multi-step work, copy this outline into `docs/plans/<TASK>.md` and fill only the sections the task needs. A small, obvious change needs only a short statement of intent and checks. A plan is a working record, not an extra approval gate.

## Outcome

- User problem and expected behavior:
- Relevant context and source-of-truth links:
- Constraints and exclusions:
- Observable completion criteria:
- Uncertainty to resolve or experiment and its decision criterion:

## Steps

List small, runnable changes in dependency order. For delegated work, name each owner, exact files, acceptance checks and integration order. Separate concurrent edits or use an isolated worktree when ownership cannot be separated.

## Verification

Select checks for the changed behavior using [the workflow](docs/agents/WORKFLOW.md). Record the command, expected observation and actual result. For UI work, include the full journey and rendered screens; separate browser, emulator and physical-device evidence. State unrun checks and remaining limits.

## Progress and handoff

- Completed work and evidence:
- Current branch/commit and relevant uncommitted changes:
- Decisions and links to their canonical record:
- Blockers or unresolved questions:
- Next concrete step:

Update this section as work changes. Do not leave a superseded plan presenting itself as current, or promote proposed behavior into a shipped claim.
