# Your first community contribution

This lesson uses a fictional room. You do not need to share your identity, upload a photograph or pay for an AI service. The map's tenant positions and the game room are separate.

## Decorate and explain a change

Prerequisites: a local Studio running from `community-studio/README.md` and the standalone game from `game/README.md`.

1. Open Studio. Change the room sign to a fictional club name.
2. Add one prop from the library, then select it. Drag it or use its numeric X/Y fields. Keep its complete bounds inside the chamfered room. Undo and redo one move.
3. Save on this device only if you want a local draft. Export the room JSON. This does not publish it.
4. Open that exported file in Godot. Compare its sign, prop type and position with Studio. If an import fails, the game should keep the previous valid room and explain the problem.
5. Write two sentences: what you changed, and what you checked. This is useful review evidence even if you have never written code.

Do not relabel the room as a real mapped company space. Do not add a classmate's name or likeness without their approval.

## Make a learning challenge

When the playable package is available, start with the fictional Contribution Club activity. Read both clues before answering. A wrong answer offers an explanation/hint and a retry; a correct answer before inspecting the clues is insufficient. The reward is awarded once. Reset explicitly starts fresh.

In Studio, keep the supported structure: two clues, three answers, one correct answer, a hint, an explanation and one reward. Edit a clue to teach a small skill you understand. Check references and reachable interaction positions before export. Have someone try it voluntarily; record confusing wording without collecting movement logs or personal profiles.

The answer is visible in the local editable package. This is practice, not a secure examination or certificate.

## Create an original character

Use the labelled appearance options and a fictional display name first. Check front/back/side facing and walking poses, not only the portrait. Introductions are optional. Keep the character's feet aligned with its pivot as it moves. Real-person portrayals need a review by that person before being distributed.

## Add a prop or improve the code

For an art contribution, create original work or use an explicitly compatible licence. Document creator/source, dimensions, transparency, crop and intended scale. The trusted catalog supplies collision and built-in interactions; JSON imports cannot load arbitrary scripts or images. A floor rug should not block movement. A secret must have an easy return.

For a coding contribution, read `CONTRIBUTING.md`, `GLOSSARY.md` and the relevant ADR. Make one observable change and test it in the matching feature package. Demonstrate the actual affected screen and note the browser or desktop target. A build alone does not prove a usable interface.

Submit review material through the repository's normal contribution process when ready. Do not publish another person's introduction, portrayal, contact details or approval records in a public package. Human contributors can work without an AI subscription; any AI assistance should be disclosed and reviewed like other draft work.
